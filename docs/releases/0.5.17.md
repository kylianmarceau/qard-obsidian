Qard 0.5.17 fixes local models failing the note-tool check even though they support tools.

- **Local tool calls:** requests using note tools no longer force the response into the final answer's JSON schema. That constraint could make Ollama return a made-up answer instead of calling a tool, causing the connection check and note-reading tasks to fail. The schema remains in the prompt, and Qard still parses and validates the final answer.
- **Clearer connection checks:** setup now shows which check failed and its actual reason. A save failure is reported separately from a model or connection failure.
- **Time to load:** the connection check allows up to three minutes for slower model startup. You can still cancel it or close the setup window at any time.

The failure was reproduced with Ollama and `gemma4:12b`. The corrected synthetic JSON and note-tool round trip passes with all four installed models: `gemma4:12b`, `qwen3.5:4b`, `qwen3.5:9b` and `gpt-oss:20b`, without reading any vault notes.

All 608 automated tests, formatting, type checking, source and stylesheet lint, build and release checks pass locally.

To install manually, download `main.js`, `manifest.json` and `styles.css` from this release and replace those three files in your vault's `.obsidian/plugins/qard/` folder. Reload Qard to apply the update. Keep `data.json`, the `study-backups` folder and your vault notes to preserve settings and study progress.
